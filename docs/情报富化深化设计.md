## 2. 五层管线在 Worker 里的落地顺序

Worker 领取 `status=new` 记录后，**按层执行，免费层永远在付费层之前**：

```
L0 采集即富化（采集器内嵌，已实现）→ kev/epss/ai_matched/ai_component/source_tier
L1 确定性富化（纯脚本，毫秒级，写进 worker 领取后第一步）
    ├─ CPE 解析 → affected_component（cpe:2.3:a:vendor:product → vendor/product）
    ├─ GitHub Advisory 版本区间 → affected_versions（免费！不用 LLM 查 PyPI）
    ├─ 文章正文/标题正则抽 CVE 编号 → article_cve 关联表（"关联分析文章"的字面实现）
    └─ 组件归一化 → components 表（langchain/LangChain/ラングチェーン → langchain）
L2 LLM Gate（1 次调用，~500 token）：判 is_ai_security，false → status=skipped
L3 LLM 富化 Agent（工具循环 ≤3 轮）：产出上述 enrich_json 其余字段
L4 情报产品（定时任务，非单记录）：情报卡片、AI-Sec 评分、简报 v2
```

**关键成本优化（对搭建文档 5.2 的修正）**：`get_pypi_versions` 从 Agent 工具降级为 L1 确定性步骤——GitHub Advisory 采集时就带回了精确版本区间（`>=0.1,<0.3.5`），LLM 只在"包名都对不上"时才值得调工具。**省下最常见的一类工具调用**。

## 3. L3 富化 Agent 流程细化（CVE 流水线）

```
第一步（零工具）：LLM 判 is_ai_security + subcategory + summary_zh + attack_type
  └─ false → skipped；true → 继续
第二步（工具循环，≤3 轮，Agent 自主决定顺序）：
  典型路径：search_github_poc(CVE号) → search_arxiv(组件名+attack_type)
  └─ 新增本地工具 get_kev_epss(cve_id)：直接查本地 cve 表（零成本零延迟，
     Agent 不该联网查我们已经有的数据——这也是答辩可讲的工程细节）
第三步：拼装 enrich_json → schema 校验 → 写回 → status=enriched
```

工具 JSON Schema（写给 agent.py 的定义）：

```json
{"name": "search_arxiv", "description": "检索 arXiv 论文",
 "parameters": {"query": "string, 英文检索词如 'prompt injection langchain'"}}
{"name": "search_github_poc", "description": "GitHub 搜 CVE 的 PoC 仓库",
 "parameters": {"cve_id": "string, 如 CVE-2026-1234", "min_stars": "int, 默认 3"}}
{"name": "get_kev_epss", "description": "查本地已富化的 KEV/EPSS 数据",
 "parameters": {"cve_id": "string"}}
```

工具实现注意（我方实测踩坑，直接抄）：
- `search_arxiv`：**必须用脚本式 UA**（`xxx-collector/0.1 (research)`），浏览器 UA 会被 406；偶发 502 需重试；查询间隔 ≥3 秒
- `search_github_poc`：`GET /search/repositories?q=CVE-2026-1234+in:name`，带 token（60→5000 次/时），star<3 的过滤掉（噪声大）
- 三工具异常都**回传文本给 Agent**（"工具暂不可用"），让它换路——不中断循环

## 4. 提示词（适配本字段名的定稿版，全文见 `富化提示词.md`）

- **通用 System（铁律）**：只依据输入文本、没有就 null、仅输出 JSON、禁止编造 CVE/版本号——temperature=0.1 + JSON 输出模式
- **CVE 富化**：输入 = description + cvss + CPE + kev/epss（中英混合），输出 = is_ai_security/subcategory/summary_zh/attack_type/fix_suggestion/attack_chain
- **文章富化（轻流水线，一次调用）**：输出 = is_ai_security + summary（50-100字）+ cve_ids[] → 写 article_cve 表；false → skipped
- 抽检纪律：每批 5% 人工看，重点盯**编造 CVE 号**和**版本号张冠李戴**

## 9. 富化流程优化清单（2026-09-25，对搭建文档 v2 的增量复核）

> 搭建文档 v2 已吸收：KEV/EPSS 进表、CWE 确定性提取、JSON/function-calling 互斥处理、
> 放量闸门、水位表、两层去重。以下为剩余优化，核心思路=**三个"调用次数缩减器"**。

**一级（必做，~1 天，成本再降 70%+）**：
1. **规则短路 LLM gate**：ai_matched=1（词边界正则+CPE 命中）→ 跳过相关性判定直接进工具循环；规则+来源双否 → 直接 skipped 不进队列。队列 24k→~1.5k，gate 调用砍 90%。LLM 只判"规则拿不准的灰区"——确定性与智能分工的答辩故事
2. **浅 gate 批量化**：RSS 日增的 gate 从单条改 20 条一调用（编号列表→JSON 数组，漏答单独补），成本再降 90%
3. **工具结果缓存**：search_arxiv/search_github_poc 按 query 缓存 sqlite（TTL 7 天）——同组件 100 个 CVE 的论文查询 100 次→1 次，同时救限流额度

**二级（实现细节，真金白银）**：
4. 重试保留 messages 历史（不重跑已成功的工具轮）
5. 并发 5→10-20（配置化实测；2k 条 2 小时→30 分钟）
6. Worker 优先级队列：kev=1 > ai_matched=1 > 其余
7. 向量化攒批（每 30s 或 20 条批量 embed，BGE 批量效率数倍）

**三级（可选/答辩素材）**：同组件+同 CWE 模板复用（复用 attack_chain/fix_suggestion，差异更新版本区间，需讲清复用边界）；成本可观测（每千条 token/花费进大盘）；NVD 描述 HTML 实体清洗。

## 10. 同一漏洞多文章的处理设计（2026-09-25 定稿）

**原则**：同漏洞的不同文章=多源证据，不是重复数据——不删、不合并行；CVE 是聚合锚点（同一漏洞一行，已实现），文章之间做"簇"。

**三种情况**：
| 情况 | 处理 |
|---|---|
| URL 相同/仅追踪参数不同 | 已解决：URL 规范化 + url_hash 唯一索引 |
| 转载/洗稿（内容基本相同） | 聚簇：选 canonical（正文最全/来源级别最高/最早），其余 same_as；正文只留 canonical（省空间省向量化），URL/来源全保留（引用显示"多家报道"） |
| 同题不同文（深度分析 vs 快讯） | 全部保留（互补资产：一篇 PoC 复现+一篇修复口径），挂同一 CVE |

**判定**：转载=标题归一化（去媒体名/标点）相似度 >0.9 + 正文 simhash >0.8；同漏洞=article_cve 关联。两个维度独立。

**数据模型**：article 表加 cluster_id + is_canonical 两列；article_cve 不变。

**下游四用法**：
1. 问答检索：同簇只喂 canonical（省 token、引用不冗余），引用栏显示"N 家来源"
2. 详情页/情报卡片：文章按簇折叠，canonical 在前
3. 可信度信号：不同簇=独立来源数，进情报置信度（source_tier 加权）——多源交叉验证的答辩点
4. 富化素材：CVE 富化只取关联文章中最长 canonical 做正文证据（省钱点）

**实现**：标题级聚类先行（半天，公众号生态标题相似度抓 80% 转载，对 no_body 微信记录尤其有效）；simhash 正文聚类二期（1 天）。

### 10.1 向量化前置的正确用法（2026-09-25 补充，回应"能否全部向量化再处理"）

**采纳**：
1. gate 三级漏斗：规则(免费) → **灰区向量近邻预筛**(免费，BGE 与已确认 AI 文章库比相似度，不像的直接 skipped) → LLM 精判(花钱)。LLM gate 量再砍一半；"规则→向量→LLM"三级递进是答辩叙事素材
2. 文档指纹向量（标题+前500字，一次 embedding，区别于切块向量）用于转载检测——比标题匹配强（抓改标题转载）；**必须高阈值 >0.93 且与标题相似度联合判定**，防误杀同题不同文

**不采纳"全部向量化进知识库"**：①语义相似≠转载（同漏洞深度文 vs 快讯相似度 0.85-0.9，纯向量聚类会误杀互补证据）；②no_body/skipped/failed 进索引会污染问答检索（设计上只收富化通过的内容）；③BGE 本地免费，这不是成本问题是质量问题——省钱的活已由三级漏斗承担。

### 10.2 同漏洞多文章最终设计：三道防线（2026-09-25 与用户对齐定稿，取代 10 的离线聚类实现方式）

**防线一：采集/入库结构质量门（全免费）**：URL 规范化+url_hash（已有）→ 批内标题归一化精确去重（已有设计）→ 正文长度门（deep_fill 后 <300 字标 low_content 不进索引——快讯短文在此拦截）→ 源级别门（聚合站 source_tier=4 深挖最低优先级）。

**防线二：向量库插入时指纹查重（BGE 免费，每篇 O(1)）**：新文章算文档指纹向量（标题+前500字，存独立 fingerprint collection，不参与问答检索）→ 查指纹库 top-1：相似度 >0.93 → 同簇，**比内容长度保长弃短**，短者标 dup_dropped（软丢弃：保留元数据行不进索引，供"N家来源"引用信号与回滚）；≤0.93 → 正常入库+登记指纹。注：深度文 vs 快讯篇幅差异大、相似度通常 <0.93 自然分簇都保留，>0.93 抓到的基本是纯转载——规则只对转载生效，安全。

**防线三：富化语义判定**：AI 相关性三级漏斗（规则→向量预筛→LLM），见 §9。

**取代关系**：本节取代 §10"标题级聚类先行+simhash 二期"的实现方式（判定思想不变：语义相似≠转载，簇内 canonical=最长）。

### 10.3 漏斗式设计的缺陷审计与最终管线（2026-09-25）

**四段并三段**：向量化一次算三用（指纹查重+灰区预筛+检索登记共用"标题+前500字"向量）。

**四个真实缺陷与对策**：
1. 级联失败（最大）：便宜层判错→贵层看不到→静默漏收不可见。对策：阈值宁松勿紧（预筛放过 90% 灰区）+ 每周抽 20 条 skipped 审计误杀率（>5% 放宽重扫）+ 人工强制 re-enrich 逃生通道
2. 向量预筛冷启动：参照库小/被污染则不准。对策：前 200 条 LLM 判定期预筛旁路运行只记录不拦截
3. 指纹边界误杀：系列文/两家独立同事件快讯可能 >0.93。对策：>0.93 且长度差 >2 倍才自动丢，长度接近进疑似簇人工队列
4. 参数复杂度 vs 数据量：日常日增几十条撑不满漏斗，省钱收益主要在回填期。对策：阈值集中 config；答辩用"回填 2.6 万条把 LLM 调用从 26k 压到 1.5k"的实测数据讲

**最终管线（三段+全程可逆）**：
```
① 结构门（URL/标题归一/长度300/源级别）—— 标记非删除，全程可逆
② 一次向量化 → 三用：指纹查重(0.93+长度差2倍→保长弃短) + 灰区预筛(旁路→生效) + 检索登记
③ LLM 幸存者：AI 相关性精判 → 富化 Agent
审计回路：每周 skipped 抽样 → 误杀率监控
```

## 11. 检索权重设计（2026-09-25，问答模块第 7 章补充）

**三处分工**：向量检索只管相似度；**重排在应用层**（top-50 → 加权 → top-5 进 LLM，不依赖向量库内置排序）；引用栏沿用重排结果。

**打分 = 硬过滤 + 软打分**：
- 硬过滤（资格）：status=enriched 才入索引｜簇内只留 canonical｜no_body 排除
- 软打分（文章）：0.45×相似度 + 0.20×来源级别 + 0.15×时效 + 0.10×深度 + 0.05×AI置信 + 多源簇数加成
- 软打分（CVE）：0.35×相似度 + 0.25×KEV + 0.15×EPSS + 0.15×严重度 + 0.10×时效
- 信号全部来自已有字段（source_tier/长度/publish_time/簇计数/KEV/EPSS）——设计连贯

**两档场景权重**（问答 Agent 意图分类顺带选档）：时效档（"最近/最新"）recency→0.30；深度档（"原理/攻击链"）depth→0.25。

**权重怎么定**：D3 评估基准 15-20 题标注"理想命中集"→ 迭代权重至 top-5 命中率平台期 → 权重表进 config。答辩口径："权重是 20 题基准上调出来的，不是拍的。"

**答辩描述**："检索质量 = 召回（向量）× 排序（多信号融合）。资格问题用硬规则，偏好问题用软打分（来源权威/时效/深度/多源交叉验证），权重由基准迭代确定且可配置。"

### 11.1 检索权重实现规格（细化版，可直接编码）

**信号归一化**：sim=1-chroma_distance（collection 必须设 hnsw:space=cosine）；tier 1/2/3/4→1.0/0.8/0.6/0.4；recency=exp(-Δdays/30)（无日期=0.5）；depth=min(1,log10(字数)/4)；ai_conf（is_ai=1→1.0，未判→0.5）；cluster_bonus=0.05×min(独立簇数,4)，总分 clamp 1.0。

**CVE 域不走向量重排**：list_cves 的 ORDER BY kev DESC, epss DESC, cvss DESC 即 CVE 侧权重；与文章域分开，Agent 分工具调用，LLM 层汇合。

**三档权重（config，和=1）**：article_general{sim.45,tier.20,rec.15,dep.10,conf.05} / article_recent{.30,.15,.40,.05,.05} / article_deep{.35,.15,.05,.35,.05}。档位判定=关键词规则（最近/最新→recent；原理/攻击链/复现→deep；默认 general），Agent 路由时顺带判。

**重排含簇折叠**（关键决策）：向量 top-50 → 打分排序 → 每簇只留最高分进 top-k（其余转"同簇引用附注"）→ 不足 k 扩候选池至 100。同时解决重复占位与引用多样性；比检索前折叠（丢召回）/LLM 内折叠（费 token）都好。

**调参协议**：20 题基准×每题 2-5 条理想引用 → 指标 Hit@5 + MRR@5 → 坐标下降搜索（固定其余，单维 ±0.05 步进，2-3 轮收敛）→ 每轮权重与命中率记 csv（答辩的"权重不是拍的"证据）。

**边界**：无日期 recency=0.5；总分 clamp；两域不混排；候选池耗尽时降级返回不足 k 并在答案中说明。
